# Security Policy

## Supported versions

Security fixes are applied to the latest version on the `main` branch. Pre-release and historical commits may not receive patches.

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting for this repository when available. If it is not available, open a minimal issue asking the maintainer to establish a private channel; do not include exploit details, credentials, copyrighted books, personal information, or provider responses in a public issue.

Include the affected version or commit, platform, impact, minimal reproduction using synthetic data, and any suggested mitigation. Please allow a reasonable period for investigation and coordinated disclosure.

## Scope priorities

Reports are especially welcome for credential exposure, unsafe local-web binding or request forgery, path traversal/ZIP extraction, source overwrite, arbitrary command execution, secret logging, provider redirects carrying credentials, or validation bypasses that publish model process text.

Translation quality disagreements without a security or integrity impact are not vulnerabilities.
